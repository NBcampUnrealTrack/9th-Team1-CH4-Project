# Overcooked 게임 시스템 분석

## 1. 게임 개요

Overcooked는 1~4명의 플레이어가 제한 시간 동안 협력하여 주문에 맞는 음식을 만들고 제출하는 협동 요리 게임이다. 핵심 재미는 복잡한 조작보다 역할 분담, 이동 동선, 작업 순서와 돌발 상황에 대응하는 과정에서 발생한다.

## 2. 한 판의 진행 구조

1. 맵과 레시피를 확인한다.
2. 플레이어가 주방의 시작 위치에 배치된다.
3. 카운트다운 후 제한 시간이 시작된다.
4. 주문 목록에 새로운 주문이 들어온다.
5. 재료를 가져와 레시피에 맞게 가공한다.
6. 가공한 재료를 조리하거나 조합한다.
7. 완성된 음식을 접시에 담아 제출한다.
8. 주문이 정확하면 점수를 얻고 연속 성공 상태를 유지한다.
9. 잘못된 음식 제출 또는 주문 시간 초과 시 불이익을 받는다.
10. 제한 시간이 끝나면 최종 점수로 별과 결과를 결정한다.

## 3. 플레이어 시스템

### 기본 행동

- 이동
- 바라보는 방향의 오브젝트 탐색
- 재료·접시·조리도구 들기
- 들고 있는 오브젝트 내려놓기
- 작업대와 상호작용
- 재료 썰기 등의 지속 작업
- 멀티플레이에서 물건 전달 및 역할 분담

### 상호작용 원칙

- 플레이어는 한 번에 하나의 운반 가능한 오브젝트만 든다.
- 빈손일 때는 대상 오브젝트를 집는다.
- 물건을 들고 있을 때는 빈 작업대에 내려놓는다.
- 조합 가능한 대상이라면 현재 물건을 대상에 합친다.
- 작업 대상에 따라 짧은 상호작용과 지속 상호작용을 구분한다.

## 4. 재료 시스템

### 재료 상태

```text
원재료 → 가공된 재료 → 조리 중 → 조리 완료 → 탄 음식
```

- 모든 재료가 모든 상태를 사용하는 것은 아니다.
- 레시피가 요구하는 상태와 일치해야 접시 또는 조리도구에 들어갈 수 있다.
- 조리 완료 후 방치하면 타기 시작하는 재료가 존재한다.
- 탄 음식은 정상 제출할 수 없고 버린 뒤 조리도구를 다시 사용해야 한다.

### 권장 데이터

- 재료 종류
- 현재 가공 상태
- 필요한 가공 시간
- 필요한 조리 시간
- 탄 음식이 되기까지의 시간
- 담을 수 있는 조리도구
- 조합 가능한 재료 목록

## 5. 작업대와 조리도구

| 종류 | 역할 |
| --- | --- |
| 재료 상자 | 지정된 원재료를 계속 제공 |
| 일반 작업대 | 재료, 접시와 조리도구를 임시로 배치 |
| 도마 | 재료를 써는 지속 작업 수행 |
| 냄비·프라이팬 | 조건에 맞는 재료를 시간에 따라 조리 |
| 접시 공급대 | 깨끗한 접시 제공 |
| 설거지대 | 사용한 접시를 세척하여 재사용 가능하게 변경 |
| 쓰레기통 | 잘못 조리하거나 불필요한 내용물 제거 |
| 제출대 | 완성 음식과 현재 주문을 비교하여 결과 전달 |

맵에 따라 이동 발판, 컨베이어 벨트, 포털, 움직이는 작업대, 화재와 같은 특수 기믹이 추가된다. 특수 기믹은 기본 요리 규칙을 바꾸기보다 플레이어의 동선과 협업 난도를 높이는 역할을 한다.

## 6. 레시피 시스템

레시피는 완성 음식에 필요한 재료와 각 재료의 상태, 조리도구, 조합 순서를 정의한다.

예시:

```text
양파 수프
양파 3개 → 각각 썰기 → 냄비에 넣기 → 끓이기 → 접시에 담기 → 제출
```

### 권장 레시피 데이터

- 레시피 ID
- 표시 이름과 아이콘
- 필요한 재료 목록
- 각 재료의 요구 상태
- 필요한 조리도구
- 완성 음식 판정 조건
- 주문 제한 시간
- 기본 점수

레시피를 코드에 직접 작성하지 않고 데이터 에셋이나 데이터 테이블로 관리하면 음식 추가 시 시스템 코드를 수정하지 않아도 된다.

## 7. 주문 시스템

### 주문 생성

- 라운드에서 사용할 수 있는 레시피 중 하나를 선택한다.
- 주문 제한 시간을 설정하고 대기열에 추가한다.
- 동시에 표시할 최대 주문 수를 제한한다.
- 주문이 완료되거나 만료되면 다음 주문을 생성한다.

### 주문 상태

```text
생성 → 대기 중 → 성공 또는 만료
```

### 제출 판정

1. 제출된 접시의 음식 구성을 읽는다.
2. 대기 중인 주문과 재료 종류 및 상태를 비교한다.
3. 일치하는 주문이 있으면 성공 처리한다.
4. 남은 주문 시간과 연속 성공 상태를 이용해 점수를 계산한다.
5. 일치하는 주문이 없으면 잘못된 제출로 처리한다.

먼저 들어온 주문부터 비교하는 방식이 기본이며, 완성 음식과 일치하는 가장 앞쪽 주문을 선택할 수 있다.

## 8. 점수와 결과 시스템

### 점수 요소

- 레시피 기본 점수
- 빠른 제출에 따른 보너스
- 연속 성공에 따른 팁 또는 배수
- 잘못된 음식 제출 페널티
- 주문 만료에 따른 연속 성공 초기화 또는 감점

### 결과 처리

- 제한 시간 종료 시 추가 주문 생성을 중단한다.
- 진행 중인 상호작용과 제출을 막는다.
- 최종 점수를 별 기준 점수와 비교한다.
- 획득한 별, 최종 점수와 성공 주문 수를 결과 화면에 전달한다.

## 9. 시간과 게임 상태

```text
인원 대기 → 카운트다운 → 플레이 → 종료 처리 → 결과
```

| 상태 | 처리 내용 |
| --- | --- |
| 인원 대기 | 플레이어 접속과 준비 확인 |
| 카운트다운 | 캐릭터 조작 제한, 시작 숫자 표시 |
| 플레이 | 시간 감소, 주문 생성, 조리와 제출 허용 |
| 종료 처리 | 주문과 조작 중단, 최종 결과 계산 |
| 결과 | 점수와 별 표시, 재시작 또는 다음 맵 선택 |

## 10. 멀티플레이 권한 구조

리슨 서버 방식에서는 호스트 서버가 게임 결과에 영향을 주는 모든 값을 결정한다.

### 서버 담당

- 플레이어 참가와 슬롯 배정
- 게임 상태와 남은 시간
- 주문 생성과 만료
- 재료 상태 변경
- 조리 진행과 완료
- 접시 조합 및 제출 판정
- 점수, 연속 성공과 최종 결과

### 클라이언트 담당

- 입력 전송
- 서버에서 받은 캐릭터와 오브젝트 상태 표시
- 카메라 출력
- 주문, 시간, 점수 UI 갱신
- 효과음과 시각 효과 재생

클라이언트가 요청한 집기, 내려놓기, 가공과 제출은 서버가 거리, 대상 상태와 현재 게임 상태를 검사한 후 승인해야 한다.

## 11. UI 구성

- 게임 시작 카운트다운
- 플레이 남은 시간
- 현재 주문 목록과 주문별 남은 시간
- 현재 점수
- 연속 성공 또는 팁 상태
- 플레이어 식별 표시
- 조리 진행도와 타기 직전 경고
- 결과 점수와 별

UI는 게임 상태를 직접 변경하지 않고 게임 상태, 주문 시스템과 조리 오브젝트가 전달하는 이벤트를 받아 표시한다.

## 12. 우리 프로젝트의 담당 연결

| 담당 영역 | 구현 대상 |
| --- | --- |
| 게임모드·코어 | 게임 상태, 시간, 주문, 제출 판정, 점수, 결과, 서버 권한 |
| 캐릭터·오브젝트 | 이동, 상호작용, 운반, 재료 상태, 작업대, 조리도구, 접시 |
| UI | 주문 목록, 시간, 점수, 진행도, 결과 화면 |
| 맵·레벨 | 주방 배치, 시작 위치, 카메라, 이동 동선, 특수 기믹 |

## 13. 구현 우선순위

1. 상호작용 인터페이스와 운반 가능한 오브젝트
2. 재료 종류와 가공 상태 데이터
3. 작업대, 도마, 냄비와 접시
4. 데이터 기반 레시피
5. 주문 생성과 만료
6. 제출 판정과 점수
7. 주문·시간·점수 UI 연결
8. 설거지, 탄 음식과 화재
9. 맵 특수 기믹과 난이도 조절
